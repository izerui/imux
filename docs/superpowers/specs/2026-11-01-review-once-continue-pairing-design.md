# 审查一次后继续结对编程

## 背景

终端工具栏的结对编程菜单有两个入口：

| 入口 | 立即审查刚完成的这一轮 | 之后每轮自动审查 | 可填审查要求 |
|---|---|---|---|
| 菜单里选伙伴（开启结对编程） | 否，等下一轮完成 | 是 | 否 |
| 审查一次 | 是 | 否，审查完自动关闭 | 是 |

用户需要第三种组合：会话没开结对编程、一轮已经做完时，先审查这一轮，审查完直接进入结对编程，由伙伴与主会话自动多轮往来直到结束。

现有实现里，“审查一次”就是“临时绑定 + 打单次标记 + 立即跑一轮 + 跑完解绑”（`PeerCoordinator.reviewOnce`）。新需求等于去掉最后的解绑，难点在交互与边界行为。

## 已确认的选择

1. 入口放在“审查一次”对话框里，加一个勾选框；菜单里选伙伴的行为不变。
2. 对话框里的审查要求只用于这一次审查，之后自动审查的各轮不带。
3. 勾选框每次打开对话框都默认不勾。

## 交互

对话框在“审查要求”下方增加：

- 勾选框：`审查后继续结对编程`
- 说明文字：`之后每轮完成都由所选智能体自动审查，审查要求只用于这一次`

不勾时行为与现在完全一致。勾选后点确定：立即审查刚完成的这一轮（带审查要求）；审查结束后不解绑，状态与从菜单选伙伴开启的结对编程相同，菜单、状态条、结果 chip 都按普通结对显示。

文案新增两条键，写进 `ImuxBundle.properties` 与 `ImuxBundle_zh_CN.properties`，其他语言回退到英文。

## 运行规则

首次审查之后，一律按普通结对编程的现有规则执行：

- **轮次计数沿用现有规则**：只有反馈成功自动发送到主会话（`injectFeedback` 成功）才计一轮；PASS、审查失败、反馈只填入输入框（关闭自动发送时）都不计数。首次审查也遵守这条规则：首次反馈成功自动发送后计为 1 轮，首次 PASS 或失败不计。
- **首次有反馈并成功发送**：主会话开始并完成下一轮后自动再次审查，这一轮及之后都不带首次的审查要求；循环到 PASS 或达到最大轮次为止。
- **首次 PASS**：保持结对，等用户下一次发消息、主会话完成后自动审查。
- **取消首次审查**：只取消这一轮，保持结对（“审查一次”取消时会解绑，这里不同）。
- **首次审查失败**：保持结对；失败提示里的“重试”仍带首次的审查要求，重试成功之后的各轮不再带。
- **用户发新消息、会话切换或迁移、停止结对**：与普通结对编程相同。

## 实现

采用“普通结对 + 立即手动跑一轮”：

- `PeerCoordinator.reviewOnce` 增加参数 `keepPairing: Boolean`（默认 `false`，现有调用不变）。为 `true` 时先 `bind`，不登记 `oneShotSessions`，立即启动一轮审查。之后所有分支（审查结束、新一轮开始、取消、迁移、轮次上限）走普通结对路径，不新增针对“继续结对”的判断。
- 审查要求改为挂在本轮的 `PeerRun` 上（新增字段），`runReviewAndInject` 拼接提示词与生成 `PeerOutcome` 时读取本轮的要求。单次审查仍从 `oneShotSessions` 取要求，行为不变。要求随这一轮结束而失效，后续自动审查的轮次天然不带。
- 失败重试：已结对且失败结果带审查要求时，走同一个“立即审查一轮”的入口并带上 `outcome.instruction`；失败结果不带要求时仍调用 `onTurnCompleted`，与现在一致。
- 对话框 `ReviewOnceDialog` 增加勾选框，`showReviewOnceDialog` 把勾选结果传给 `reviewOnce`。

不采用的方案：沿用单次标记、加“结束后不解绑”开关。需要在审查结束、新一轮开始、取消、迁移四处分别判断，漏一处就会出现“有时自动关闭”的问题。

## 测试

用 `PeerCoordinatorDispatchTest` 的脚手架（替换 `runCli`、`sendAutoFeedback`，手动驱动 `onTurnStarted` / `onTurnCompleted`），断言完整行为链，而不只是断言绑定还在：

1. **主链路**：`keepPairing = true` 且带要求 → 首次审查返回反馈 → 成功自动发送 → 主会话 `onTurnStarted`、`onTurnCompleted` → 自动发起第二次审查；断言第一次提示词带要求、第二次不带，且两轮之间始终处于结对状态。
2. **轮次上限为 1**：首次反馈成功发送后，主会话完成下一轮时不再发起第二次审查，并报告达到上限。
3. **首次失败重试**：首次审查失败 → 保持结对 → 重试，提示词仍带要求 → 重试返回反馈并成功发送 → 主会话完成下一轮后的自动审查不带要求。
4. **首次 PASS 与只填入输入框都不计轮次**：PASS 后保持结对；关闭自动发送时反馈只填入输入框，轮次不增加。
5. **取消首次审查**：取消后保持结对。
6. **不勾选回归**：现有单次审查相关测试全部照常通过（审查完解绑、取消解绑、新一轮开始解绑）。
