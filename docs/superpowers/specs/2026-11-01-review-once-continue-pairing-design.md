# 审查一次后继续结对编程

## 需求

“审查一次”对话框加一个勾选框“同时开启结对编程”。勾选后点确定，两个功能在确认时都触发：

1. 开启结对编程：用对话框里选的智能体，状态等同于在菜单里点选这个伙伴。
2. 审查一次：立即审查刚完成的这一轮，带上对话框里填的审查要求。

审查要求只用于这一次审查；之后结对编程自动发起的各轮不带。除此之外不新增任何组合规则，后续一切按普通结对编程的现有逻辑执行。

勾选框每次打开对话框都默认不勾；不勾时行为与现在完全一致。

## 行为

确认后界面立即进入结对编程状态（菜单、状态条显示结对，当前这一轮显示为正在审查）。之后都是普通结对编程的现有逻辑：

- 轮次计数沿用现有规则：只有反馈成功自动发送到主会话才计一轮；PASS、失败、只填入输入框都不计。这次审查同样适用，它的反馈成功自动发送后计为 1 轮。
- 这次审查的反馈发送后，主会话完成下一轮时自动再次审查（不带审查要求），循环到 PASS 或达到最大轮次。
- 取消这一轮审查：只取消这一轮，结对保持（普通结对的取消语义）。
- 停止结对编程：立即停止，正在进行的审查一并取消，之后不再自动审查。
- 审查失败后的“重试”：按普通结对的现有逻辑重新审查，不带这次的审查要求。

## 实现

- `PeerCoordinator.reviewOnce` 增加参数 `keepPairing: Boolean = false`。为 `true` 时：`bind` 后不登记 `oneShotSessions`，立即启动一轮审查。之后所有分支（审查结束、新一轮开始、取消、停止、迁移、轮次上限）都走普通结对路径，不新增针对组合的判断。
- 审查要求改为挂在本轮的 `PeerRun` 上（新增字段）：`runReviewAndInject` 拼接提示词、生成 `PeerOutcome` 时读本轮的要求。单次审查（不勾选）把要求同样放到它那一轮的 `PeerRun` 上，行为不变。要求随这一轮结束失效，结对后续各轮自然不带。
- `ReviewOnceDialog` 增加勾选框，`showReviewOnceDialog` 把勾选结果传给 `reviewOnce`。文案新增一条键（`ImuxBundle.properties`、`ImuxBundle_zh_CN.properties`，其他语言回退英文）。

## 测试

用 `PeerCoordinatorDispatchTest` 的脚手架（替换 `runCli`、`sendAutoFeedback`，手动驱动 `onTurnStarted` / `onTurnCompleted`），断言行为链而不只是绑定状态：

1. **确认即结对**：`keepPairing = true` 调用后，审查完成之前 `boundTarget` 已是所选智能体。
2. **主链路**：这次审查返回反馈并成功自动发送 → 主会话 `onTurnStarted`、`onTurnCompleted` → 自动发起第二次审查；断言第一次提示词带审查要求、第二次不带，全程保持结对。
3. **轮次上限为 1**：这次审查的反馈成功发送后，主会话完成下一轮时不再发起审查，并报告达到上限。
4. **PASS 后保持结对**，且不发起额外审查；关闭自动发送时反馈只填入输入框，轮次不增加。
5. **取消这一轮**：取消后保持结对。
6. **审查期间停止结对**：停止后解绑、审查被取消；之后主会话完成新一轮也不再发起审查。
7. **不勾选回归**：现有单次审查测试全部照常通过（审查完解绑、取消解绑、新一轮开始解绑、失败重试带要求）。
