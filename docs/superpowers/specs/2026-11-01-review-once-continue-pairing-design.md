# 审查一次后继续结对编程

## 需求

“审查一次”对话框加一个勾选框“同时开启结对编程”。勾选后点确定，两个现有功能都触发：

1. 审查一次：完全按现在的行为执行（选的智能体、填的审查要求都照旧）。
2. 开启结对编程：用对话框里选的智能体，效果等同于在菜单里点选这个伙伴。

两者之间不传递任何参数，也不新增针对组合的规则。效果等于用户手动先点“审查一次”、再去菜单里点伙伴。

勾选框每次打开对话框都默认不勾；不勾时行为与现在完全一致。

## 为什么是“先后”而不是“同时”

两个功能共用同一个结对槽位：`reviewOnce` 在已绑定时直接返回；`bind` 会取消正在进行的审查。所以实现上按顺序触发：先启动审查一次，它结束、释放槽位后立即开启结对编程。

“结束”包括单次审查释放槽位的所有情况：PASS、有反馈、失败、用户取消、主会话开始新一轮（收到反馈后主会话开工，也会结束单次审查）。无论哪种，结束后都开启结对编程。会话迁移或项目关闭时不开启（原会话已不存在）；用户在审查期间已经手动开启了结对或换了伙伴，以用户的选择为准，不再开启。

## 行为

- 审查期间，界面显示的是单次审查的状态；审查结束后显示结对编程状态。
- 单次审查的反馈自动发送后，主会话开始新一轮，此时结对编程已开启，这一轮完成后自动审查，之后按普通结对编程循环。
- 结对编程的轮次从 0 开始计，单次审查不占用结对的轮次上限（与手动先后操作一致）。
- 重试、取消、停止、轮次上限等全部是两个功能各自的现有逻辑。

## 实现

- `ReviewOnceDialog` 增加勾选框，文案新增一条键（`ImuxBundle.properties`、`ImuxBundle_zh_CN.properties`，其他语言回退英文）。
- `PeerCoordinator` 增加“单次审查结束后开启结对”的待办：`reviewOnce` 接收可选参数 `thenPairWith: AgentType?`，记在单次审查的登记信息里。
- 单次审查现有的几处结束出口（审查跑完、取消、主会话开始新一轮）收拢到一个内部函数：解绑后若有待办就调用 `bind`。会话迁移、`dispose` 不执行待办。
- 待办只在槽位仍为空时执行：若单次结束时该会话已被用户重新绑定，就丢弃待办。

## 测试

用 `PeerCoordinatorDispatchTest` 的脚手架（替换 `runCli`、`sendAutoFeedback`，手动驱动 `onTurnStarted` / `onTurnCompleted`）：

1. **主链路**：勾选 → 单次审查返回反馈并自动发送 → 主会话 `onTurnStarted`（单次结束、开启结对）→ `onTurnCompleted` → 自动发起结对审查；断言此时处于结对状态、第二次审查确实发生且是普通结对审查（提示词不带单次要求）。
2. **单次 PASS 后开启结对**：PASS 后处于结对状态，且未发起额外审查。
3. **单次失败、取消后都开启结对**。
4. **轮次从 0 开始**：最大轮次设为 1，单次反馈发送后，结对的第一轮审查仍会发生。
5. **用户中途已绑定**：单次审查期间用户手动开启了别的伙伴，单次结束后不覆盖用户的选择。
6. **会话迁移**：单次审查期间迁移，不开启结对。
7. **不勾选回归**：现有单次审查测试全部照常通过。
