# 会话内 Codex 式提问导航设计

日期：2026-11-05

## 背景

会话终端右侧现有一条消息导航轨道（`SessionMessageNavigator`）：竖线 + 圆点，悬停弹平台 Balloon 气泡，点击跳转。用户反馈两个问题：

1. 交互形态不理想，希望改成 Codex 那种左侧短横线 + 悬停卡片；
2. 圆点“定位不准”：点击后跳不到对应的用户输入，或长提问根本没有圆点。

本设计先修定位，再替换交互形态。transcript 解析、增量刷新、副驾驶反馈锚点（`peerFeedbackAnchors`）等现有机制保持不变。

## 一、定位不准的根因

点击跳转本身正确（滚动到锚点 offset 并居中），错误来自锚点匹配 `locateUserMessageAnchorsIndexed`。已用复刻逻辑验证以下三处：

### 1. 中文长提问被 TUI 硬换行后整条失配

TUI 在行尾硬换行并缩进续行。现有归一化把连续空白折叠成一个空格，终端文本变成“…只生 成盐和水…”，比 transcript 原文多一个空格，`lastIndexOf` 失败，该轮没有锚点。英文在空格处断行不受影响，中文长提问几乎全部中招。

### 2. 回复 markdown 失配，提问被复述抢走

transcript 中的 `assistantReply` 是原始 markdown（`**继续**`），终端显示渲染后文本，回复匹配失败、游标不前移。回复原本是挡在“提问”与“回复内复述”之间的边界，边界失效后提问会匹配到回复或工具输出中的同文。复现：提问“继续”应在第 0 行，实际落到第 4 行的“继续 执行测试”。

### 3. 用户输入色块读取越界与覆盖不全

- `idea.log` 中有 `highlighting reflection failed: IndexOutOfBoundsException (toIndex 22763 > size 22717)`。终端快照与高亮区间分两次读取，中间终端有新输出，偏移失效；异常后整轮退回纯文本匹配。
- 色块区间只取到首行行尾，判定要求整个 needle 落在区间内，多行提问永远走不到优先匹配。
- 逐字符反射调用 `getHighlightingAt`，扫描 256K 字符时开销很大。

## 二、定位修复

### 匹配归一化

新增“匹配用归一化”：两侧只保留 `Character.isLetterOrDigit` 为真的字符（中日韩文字计入），丢弃空白、标点、markdown 符号、TUI 前缀与边框，同时保留到原文 offset 的映射。

- 用户提问 needle：归一化后前 `MATCH_PREFIX_CHARS`（120）个字符；
- 回复 needle：归一化后前 `REPLY_MATCH_CHARS`（40）个字符，减少回复中途出现表格、链接、代码块导致的失配；
- 归一化后为空的轮次（纯符号、纯图片）跳过，与现状一致；
- 预览文本（`userPreview` / `replyPreview`）仍使用现有空白折叠，不受影响。

锚点 offset 取匹配首字符对应的原文位置，跳转时落在提问正文首字，而不是前缀符号。

起点选择：前缀只用来找候选。提问内部有循环重复片段时同一前缀会在一条输入里出现多次，因此每个候选都用完整输入验证，优先级为：整段对上且起点在色块内 > 整段对上 > 仅前缀对上但在色块内 > 仅前缀对上的最后一处。同档取最靠后的，保持重复提问按轮次分开的既有规律。

### 色块优先匹配

- 判定改为“匹配起点的绝对 offset 落在某个色块区间内”，多行提问也能命中；
- 终端快照与色块区间在同一个 `ReadAction` 中读取；
- 改用 `TerminalOutputModel.getHighlightings()` 一次拿到高亮快照再遍历，替代逐字符 `getHighlightingAt`，仍走反射（Internal API），异常时降级为空列表；
- 色块区间裁剪到快照的 `[scanStart, endOffset]` 范围内。

### 回归测试

在 `SessionMessageNavigatorTest` 补充：

- 中文长提问被硬换行 + 续行缩进后仍定位到首字；
- 回复含 `**粗体**`、行内代码、列表符号时，提问不被回复内复述抢走；
- 多行提问的起点在色块内时优先命中色块位置；
- 现有用例（重复提问、裁剪、前缀、复述等）全部保持通过，期望值不变。

## 三、Codex 式导航 UI

### 横线列（左侧悬浮）

- 位于终端左边缘上层（`JLayeredPane.PALETTE_LAYER`），不改终端尺寸，TUI 不重排；
- 每条用户输入一根短横线，无竖线；
- 横线等间距、整列垂直居中，间距 `TICK_GAP`（8px）；总高超出可用高度时按比例压缩间距，最小 `TICK_MIN_GAP`（3px）；纵向位置与输入在文档中的位置无关；
- 常态：暗灰色，长度按提问字数分三档（8 / 11 / 14px）；
- 强调态（视口内的输入，或鼠标悬停那根）：长度 20px、加粗、高亮色；两种强调同一尺寸，避免点击后鼠标移开时横线“缩一下”；
- 鼠标事件穿透：横线列组件覆盖 `contains(x, y)`，只在命中区返回 true。Swing 按 `contains` 逐层查找最深组件，非命中点直接落到下层终端，终端点击、拖选文本、滚轮都不受影响，不做事件转发；
  - 命中区：横向为横线实际长度 + 2px 余量（未悬停时按该横线自身长度，而不是整列宽度），纵向为该横线上下各 `min(间距/2, 4px)`；
  - 命中判断由纯函数 `tickHitIndex(x, y, ticks)` 计算，返回命中横线下标或 null，`contains` 与鼠标处理共用；
  - 卡片组件只在悬停时可见，隐藏后不参与命中；卡片本身覆盖的终端区域在显示期间不可点击，这与原 Balloon 行为一致；
- 去除右侧轨道、竖线、圆点。

纵坐标由纯函数 `tickY(index, count, height, padding)` 计算，替代 `markerY`，并有单测覆盖：居中、等距、压缩、单条、空列表。

### 悬停卡片

- 鼠标悬停横线时，在横线右侧显示卡片，卡片纵向中心对齐横线，贴近上下边界时收进可视区；
- 卡片内容：
  - 首行灰色小字：`n/N · 会话标题`（标题取 `AgentTerminalVirtualFile.tabTitle`）；
  - 加粗提问，最多 2 行，超出省略；
  - 灰色回复摘要，最多 2 行；无回复时隐藏；
- 圆角、阴影，无尖角；
- 实现为终端层 `JLayeredPane.POPUP_LAYER` 中的普通组件，不再使用 Balloon：换一根横线只移动位置、更新文字，不重建，不闪烁，也不存在首次点击被气泡吞掉的问题；
- 保留延迟隐藏（`HIDE_DELAY_MS`），鼠标在横线边缘抖动时不闪；切换标签页时隐藏。

### 点击

- 滚动到该输入并居中（`ScrollType.CENTER`），卡片保持显示；
- 在终端中给该输入加约 1.5 秒的高亮底色后移除（`RangeHighlighter`），让落点一眼可见；范围覆盖整段输入：起点用前 120 个有效字符定位后，沿该轮完整输入继续逐字比对，直到对不上或碰到本轮回复起点为止。为此 `UserMessageAnchor` 增加 `endAbsoluteOffset`（最后一个对上的字符之后的绝对位置，副驾驶反馈锚点取提示文本长度）；
- 等间距后不存在同位置多条锚点，删除 `nextCollocatedAnchor` 及其循环点击逻辑与测试。

### 布局联动

`AgentTerminalFileEditor.doLayout`：

- 导航组件改为放在左侧：`setBounds(LEFT_INSET, 0, navigatorWidth, height)`；
- 卡片组件加入 `POPUP_LAYER`，由导航器自行定位；
- `rightReserve` 不再包含导航宽度，只保留与滚动条之间的留白；图标组与会话轨迹卡片随之右移。

## 四、文案与文档

- 卡片序号格式 `n/N` 写入 `ImuxBundle` 各语言文件；
- 更新 `docs/guide.md`「会话内消息导航」一节，以及第 231 行“放在消息导航轨道左侧”的描述。

## 五、不做的事

- 不改 transcript 解析与 `SessionExchange` 结构；
- 不给终端左侧让位，不触发 TUI 重排；
- 不新增快捷键或上一条 / 下一条按钮。

## 六、验证

- `./gradlew test` 全部通过；
- `lint_files` 检查改动文件；
- 单测：`tickHitIndex` 覆盖横线上、横线右侧空白、两根横线之间、列外、压缩间距下相邻横线不重叠；
- IDE 沙箱交互验证（以下每项都需逐条确认，目前仅有改动前的基线测试通过）：
  1. Claude Code 中文长对话（含多行提问、markdown 回复、回复中复述提问），每条提问都有横线，数量与 transcript 轮次一致；
  2. 悬停某根横线：该横线放大高亮，卡片的 `n/N`、提问、回复属于同一轮；
  3. 点击该横线：终端滚动居中，高亮底色正好落在同一轮提问的首字起，与卡片内容一致；
  4. 在横线列所在的终端左侧区域：横线之间与横线右侧空白处单击定位光标、拖选文本、滚轮滚动均正常到达终端；
  5. 卡片隐藏后，原卡片位置的终端区域可正常点击与选择。
