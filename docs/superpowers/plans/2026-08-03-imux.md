# imux 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 IntelliJ IDEA 2026.1+ 实现一个插件，左侧新增 AI Agent 工具窗口，以分组树列出当前项目的 Claude Code / Codex 会话，点击会话在 editor tab 中打开跑着该 CLI 的终端。

**Architecture:** 插件是两个 CLI 自有会话库的**视图**加**终端宿主**，零持久化。`SessionRepository`（无状态）读取 `~/.claude/projects/` 与 `~/.codex/sessions/`；`SessionListModel` 持有全部可变状态（扫描结果、未绑定的新会话临时条目、文件监听）；`TerminalHost` 拥有 Reworked 引擎的 `TerminalView` 并通过自定义 `LightVirtualFile` + `FileEditorProvider` 把它挂进 editor tab。

**Tech Stack:** Kotlin，Gradle + IntelliJ Platform Gradle Plugin 2.x，JUnit 4，IntelliJ IDEA 2026.1（构建号 261）。

## Global Constraints

以下约束适用于每一个 task，不再重复：

- **目标平台**：IntelliJ IDEA 2026.1，实测构建号 `IU-261.25134.95`。`sinceBuild = 261`，**不设 `untilBuild`**（已明确决策）。不写任何低版本兼容代码。
  - 该决策的已知后果：终端 API 属 Experimental，若未来大版本改了签名，插件仍会照常加载，然后在**点击会话的那一刻**抛 `NoSuchMethodError`（而非安装时被拒绝）。
  - 排查提示：升级 IDE 后若点击会话报 `NoSuchMethodError` / `NoSuchMethodException`，几乎必然是终端 API 漂移，对着新版 jar 重新核对 `terminal/` 包下 4 个文件的调用签名即可。爆炸半径被刻意限制在这个包内。
- **语言与工具链**（以下版本均为实测确认，不要凭记忆改）：Kotlin **2.3.21**、`jvmToolchain(21)`、Gradle **9.6.1**、IntelliJ Platform Gradle Plugin **2.18.1**。测试框架用 **JUnit 4**（`junit:junit:4.13.2`）。
  - Kotlin 必须是 2.3.x：IDEA 2026.1 的平台 jar 元数据版本是 2.3.0，用 2.1.x 编译会报 `Module was compiled with an incompatible version of Kotlin`。
  - Gradle 必须 9+：IntelliJ Platform Gradle Plugin 2.18.1 明确要求。
  - 平台依赖用 `local("/Applications/IntelliJ IDEA.app")`，不用 `intellijIdea("2026.1")`（后者要从 download.jetbrains.com 拉 1G+ 安装包）。注意 `intellijIdeaCommunity(...)` 已废弃——IC 自 2025.3 起不再单独发布。
- **根包名**：`com.github.izerui.imux`
- **零持久化**：任何 task 都不得引入 `PersistentStateComponent`、不得写入 `.idea/`、不得在插件侧存储会话数据。会话身份完全归 CLI 所有。
- **终端引擎：Reworked 2025**（枚举 `org.jetbrains.plugins.terminal.TerminalEngine.REWORKED`，2026.1 的默认引擎）。这是**明确的设计决策**，不是 API 选择的副产物。另两个取值 `CLASSIC`、`NEW_TERMINAL`（已废弃）不使用。
  - 架构事实：Reworked 只重写了**渲染前端**（基于 IDEA 的 `EditorImpl`），**VT 仿真后端仍是 JediTerm 3.68**（`terminal.jar` 中引用 jediterm 的类全在 backend 包，frontend 的 view 包引用数为 0）。因此 TUI 兼容性继承自成熟的 JediTerm。
  - 已在字节码中确认支持重型 TUI 所需特性：alternate screen buffer（`TerminalEditorFactory.createAlternateBufferEditor`）、SGR 鼠标上报（`MouseFormatDto` 含 `SGR`）、真彩（`TerminalColorDto` 有独立 `rgb` 字段）。
- **终端 API 的确切坐标**（已从本机 2026.1 的 jar 反编译确认，不要凭记忆改动）：
  - 创建入口：`org.jetbrains.plugins.terminal.TerminalToolWindowTabsManager.getInstance(Project).createTabBuilder()`
    builder 支持链式 `workingDirectory(String)` / `shellCommand(List<String>)` / `envVariables(Map)` / `closeOnProcessTermination(Boolean)` / `shouldAddToToolWindow(Boolean)` / `deferSessionStartUntilUiShown(Boolean)` / `createTab(): TerminalToolWindowTab`
  - `TerminalToolWindowTab.getView(): com.intellij.terminal.frontend.view.TerminalView`
  - `TerminalView` 暴露 `getComponent(): JComponent`、`getPreferredFocusableComponent(): JComponent`、`getTitle()`、`getSessionState(): StateFlow`、`getCoroutineScope()`
  - **不要使用**：`TerminalToolWindowManager.createShellWidget(...)` 与 `LocalTerminalDirectRunner` —— 二者的字节码锁死 `TerminalEngine.CLASSIC`，拿不到 Reworked；`ShellStartupOptions` 亦属经典引擎路径。
  - **不要使用** `TerminalViewFileEditor`：其 `dispose()` 在非 reopen 场景下执行 `cancel(terminalView.coroutineScope)`，会终止进程，与本设计的所有权规则冲突。
- **API 稳定性**：上述全部处于 `@ApiStatus.Experimental`（`TerminalToolWindowTabsManager`、`TerminalView`）或 `@ApiStatus.Internal`（`TerminalViewImpl`、`TerminalEditorFactory`、`createNewTab`）。**优先用 Experimental 的，避开 Internal 的。** 已接受跨版本签名漂移的代价——本插件只面向 2026.1 单一大版本。
- **输出容量**：Reworked 引擎按**字节**限制输出，Advanced Setting 键为 `new.terminal.output.capacity.kb`，默认 **1024 KB**。（`terminal.buffer.max.lines.count`（默认 5000 行）是**经典/Gen-2 引擎**的键，对 Reworked 无效，不要用错。）resume 会把完整历史写入输出区，长会话在默认值下开头会被截断。
- **CLI 落盘事实**（已实测确认）：
  - Claude：`~/.claude/projects/<cwd 中 / 和 . 均替换为 ->/<uuid>.jsonl`；标题来自 `{"type":"ai-title","aiTitle":"...","sessionId":"..."}` 记录，取最后一条；恢复命令 `claude --resume <uuid>`
  - Codex：`~/.codex/sessions/YYYY/MM/DD/rollout-<时间戳>-<uuid>.jsonl`；首行 `{"type":"session_meta","payload":{"id":...,"cwd":...}}`；**无标题记录**，标题回退为首条用户消息截断；恢复命令 `codex resume <uuid>`
- **解析必须容错**：任何一条会话文件解析失败，跳过该条并记日志，绝不抛异常中断整个列表。

## Task 0: 前置验证 —— IDEA 终端能否胜任这两个 TUI

**Files:** 无（纯手工验证，不写代码）

**Interfaces:**
- Consumes: 无
- Produces: 一个结论 —— 继续，或者放弃整个方案

这是**硬闸门**。整个插件的承重假设是「IDEA 的终端能正常渲染并交互 Claude Code / Codex」。若该假设不成立，后面 8 个任务全部白做。用几分钟证伪它，比写完再发现便宜得多。

**必须确认引擎停在 Reworked 2025**，因为插件用的是 Reworked 路径（见 Global Constraints）。这是 2026.1 的默认值，但要显式核对——若此前手工切过 Classic，测出的结果不代表插件表现。

- [ ] **Step 1: 确认终端引擎为 Reworked 2025**

Settings | Tools | Terminal → "Terminal engine" 下拉 → 应为 **Reworked 2025**（默认值）。若不是，切回去。

（该设置持久化在 `TerminalOptionsProvider`，不是 registry 键。旧的 `terminal.new.ui` / `terminal.new.ui.reworked` 两个 registry 键在 2026.1 已是 no-op，不要用。）

- [ ] **Step 2: 调大终端输出容量**

Settings | Advanced Settings → 搜 `new.terminal.output.capacity.kb`，默认 **1024** KB，改为 **16384**。

理由：resume 会把完整历史写进输出区，长会话在默认容量下会被截断开头。

注意别改错键：`terminal.buffer.max.lines.count`（默认 5000 行）是**经典引擎**的键，对 Reworked 无效。

- [ ] **Step 3: 在 IDEA 自带终端里跑 claude**

打开 Terminal 工具窗口（经 Step 1 确认，此时它用的是 Reworked 引擎，与插件一致），`cd` 到一个此前用过 claude 的项目，运行 `claude`。逐项确认：

1. 启动画面与边框字符渲染正常，没有错位或乱码
2. 颜色正常（区分用户/助手/工具输出）
3. 能正常输入并收到回复
4. `shift+tab` 能循环切换模式，底部状态行随之变化
5. `ctrl+o` 能展开折叠的工具调用
6. 中文显示不错位（CJK 宽字符占两列）
7. 退出后重新 `claude --resume <id>`，历史完整重放，滚到顶能看到第一条消息

- [ ] **Step 4: 同样测 codex**

在同一目录运行 `codex`，确认渲染、输入、退出正常；再 `codex resume <id>` 确认历史重放。

- [ ] **Step 5: 判定**

- **全部正常** → 记录下来，进入 Task 1
- **个别项有瑕疵**（如某个快捷键不灵）→ 记录为已知限制，可以继续，但要在 README 里写明
- **渲染严重错乱或无法交互** → **停止**。此时插件的核心价值不成立，应当先向上游反馈或重新评估方案（例如退回到「只做会话列表，点击后在系统终端打开」这种降级形态），而不是继续实现

本任务不产生提交。把结论记在 issue 或 README 草稿里即可。

`src/test/kotlin/com/github/izerui/imux/session/ClaudeSessionReaderTest.kt`：

```kotlin
package com.github.izerui.imux.session

import com.github.izerui.imux.model.AgentType
import org.junit.Assert.assertEquals
import org.junit.Assert.assertTrue
import org.junit.Rule
import org.junit.Test
import org.junit.rules.TemporaryFolder
import java.io.File

class ClaudeSessionReaderTest {

    @get:Rule
    val tmp = TemporaryFolder()

    private fun reader() = ClaudeSessionReader(tmp.root.toPath())

    /** 目录名编码：/ 与 . 都要变成 - 。实测证据见计划 Global Constraints。 */
    @Test
    fun `目录名编码将斜杠和点都替换为连字符`() {
        assertEquals(
            "-Users-izerui-github-maas-api",
            reader().projectDirName("/Users/izerui/github/maas-api"),
        )
    }

    @Test
    fun `目录名编码处理隐藏目录中的点`() {
        assertEquals(
            "-Users-izerui-github-demo--claude-worktrees-spec",
            reader().projectDirName("/Users/izerui/github/demo/.claude/worktrees/spec"),
        )
    }

    @Test
    fun `读取会话时以文件名为 id 并取最后一条 ai-title 作为标题`() {
        val dir = File(tmp.root, "projects/-Users-demo-proj").apply { mkdirs() }
        File(dir, "aaaa-1111.jsonl").writeText(
            """
            {"type":"user","message":{"content":"你好"}}
            {"type":"ai-title","aiTitle":"旧标题","sessionId":"aaaa-1111"}
            {"type":"ai-title","aiTitle":"最新标题","sessionId":"aaaa-1111"}
            """.trimIndent(),
        )

        val sessions = reader().read("/Users/demo/proj")

        assertEquals(1, sessions.size)
        assertEquals("aaaa-1111", sessions[0].id)
        assertEquals("最新标题", sessions[0].title)
        assertEquals(AgentType.CLAUDE, sessions[0].agentType)
    }

    @Test
```

```kotlin
package com.github.izerui.imux.session

import com.github.izerui.imux.model.AgentSession
import com.github.izerui.imux.model.AgentType
import com.intellij.openapi.diagnostic.logger
import java.nio.file.Files
import java.nio.file.Path
import java.time.Instant

/**
 * 读取 Claude Code 的会话库。
 *
 * 布局：<claudeHome>/projects/<cwd 编码>/<session-uuid>.jsonl
 * 编码规则：cwd 中的 '/' 与 '.' 均替换为 '-'。
 */
class ClaudeSessionReader(private val claudeHome: Path) {

    fun projectDirName(projectPath: String): String =
        projectPath.map { if (it == '/' || it == '.') '-' else it }.joinToString("")

    fun read(projectPath: String): List<AgentSession> {
        val dir = claudeHome.resolve("projects").resolve(projectDirName(projectPath))
        if (!Files.isDirectory(dir)) return emptyList()

        return Files.list(dir).use { stream ->
            stream.toList()
                .filter { Files.isRegularFile(it) && it.fileName.toString().endsWith(".jsonl") }
                .mapNotNull { readOne(it) }
        }
    }

    private fun readOne(file: Path): AgentSession? = runCatching {
        val id = file.fileName.toString().removeSuffix(".jsonl")
        AgentSession(
            id = id,
            title = extractTitle(file) ?: fallbackTitle(id),
            agentType = AgentType.CLAUDE,
            lastActiveAt = Files.getLastModifiedTime(file).toInstant(),
        )
    }.onFailure { LOG.warn("跳过无法解析的 Claude 会话文件 $file", it) }.getOrNull()

    /** 取最后一条 ai-title 记录。文件可能很大，因此逐行流式读取而非整体载入。 */
    private fun extractTitle(file: Path): String? {
        var title: String? = null
        Files.newBufferedReader(file).useLines { lines ->
            lines.forEach { line ->
                if (!line.contains(TITLE_MARKER)) return@forEach
                TITLE_REGEX.find(line)?.groupValues?.get(1)?.let { title = unescapeJson(it) }
            }
        }
        return title
    }

    private fun fallbackTitle(id: String) = "会话 ${id.take(8)}"

    private fun unescapeJson(raw: String) = raw
        .replace("\\\"", "\"")
        .replace("\\n", " ")
        .replace("\\\\", "\\")

    private companion object {
        val LOG = logger<ClaudeSessionReader>()
        const val TITLE_MARKER = "\"ai-title\""
        val TITLE_REGEX = """"aiTitle"\s*:\s*"((?:[^"\\]|\\.)*)"""".toRegex()
    }
}
```

用正则而非 JSON 库逐行解析，是因为会话文件单行可达数 MB（含完整工具输出），只为取一个标题就反序列化整行不划算，而 `ai-title` 记录本身结构极简、可靠。

```kotlin
package com.github.izerui.imux.session

import com.github.izerui.imux.model.AgentSession
import com.github.izerui.imux.model.AgentType
import com.intellij.openapi.diagnostic.logger
import java.nio.file.Files
import java.nio.file.Path

/**
 * 读取 Codex 的会话库。
 *
 * 布局：<codexHome>/sessions/YYYY/MM/DD/rollout-<时间戳>-<uuid>.jsonl
 * 与 Claude 不同，目录不按 cwd 组织，归属需读首行 session_meta 判断。
 */
class CodexSessionReader(private val codexHome: Path) {

    fun read(projectPath: String): List<AgentSession> {
        val root = codexHome.resolve("sessions")
        if (!Files.isDirectory(root)) return emptyList()

        return Files.walk(root).use { stream ->
            stream.toList()
                .filter { Files.isRegularFile(it) && it.fileName.toString().endsWith(".jsonl") }
                .mapNotNull { readOne(it, projectPath) }
        }
    }

    private fun readOne(file: Path, projectPath: String): AgentSession? = runCatching {
        val lines = Files.newBufferedReader(file).useLines { it.take(MAX_SCAN_LINES).toList() }
        val meta = lines.firstOrNull() ?: return null
        if (!meta.contains(META_MARKER)) return null

        val cwd = CWD_REGEX.find(meta)?.groupValues?.get(1) ?: return null
        if (cwd != projectPath) return null

        val id = ID_REGEX.find(meta)?.groupValues?.get(1) ?: return null

        AgentSession(
            id = id,
            title = firstUserMessage(lines)?.let(::truncate) ?: "会话 ${id.take(8)}",
            agentType = AgentType.CODEX,
            lastActiveAt = Files.getLastModifiedTime(file).toInstant(),
        )
    }.onFailure { LOG.warn("跳过无法解析的 Codex 会话文件 $file", it) }.getOrNull()

    private fun firstUserMessage(lines: List<String>): String? = lines
        .asSequence()
        .filter { it.contains(USER_ROLE_MARKER) }
        .mapNotNull { TEXT_REGEX.find(it)?.groupValues?.get(1) }
        .firstOrNull()
        ?.replace("\\n", " ")
        ?.replace("\\\"", "\"")

    private fun truncate(text: String): String =
        if (text.length <= TITLE_MAX) text else text.take(TITLE_MAX) + "…"

    private companion object {
        val LOG = logger<CodexSessionReader>()

        /** 只扫前若干行找首条用户消息，避免为一个标题读完整个大文件。 */
        const val MAX_SCAN_LINES = 50
        const val TITLE_MAX = 60

        const val META_MARKER = "\"session_meta\""
        const val USER_ROLE_MARKER = "\"role\":\"user\""

        val CWD_REGEX = """"cwd"\s*:\s*"((?:[^"\\]|\\.)*)"""".toRegex()
        val ID_REGEX = """"id"\s*:\s*"([^"]+)"""".toRegex()
        val TEXT_REGEX = """"text"\s*:\s*"((?:[^"\\]|\\.)*)"""".toRegex()
    }
}
```

```kotlin
class SessionRepository(

    private val codexReader: CodexSessionReader,

            return SessionRepository(
                ClaudeSessionReader(home.resolve(".claude")),
                CodexSessionReader(home.resolve(".codex")),
            )
        }
    }
}
```

## Task 5: 会话列表状态与新会话绑定

**Files:**
- Create: `src/main/kotlin/com/github/izerui/imux/session/SessionListModel.kt`
- Test: `src/test/kotlin/com/github/izerui/imux/session/SessionListModelTest.kt`

**Interfaces:**
- Consumes: `SessionRepository`（Task 4）、`AgentSession`、`AgentType`
- Produces:
  - `data class PendingSession(val key: String, val agentType: AgentType, val startedAt: Instant)`
  - `sealed interface ListEntry`，含 `data class Existing(val session: AgentSession) : ListEntry` 与 `data class Pending(val pending: PendingSession) : ListEntry`
  - `class SessionListModel(scan: () -> List<AgentSession>, clock: () -> Instant)`，含
    - `fun registerPending(agentType: AgentType): PendingSession`
    - `fun refresh()`
    - `fun entries(agentType: AgentType): List<ListEntry>`
    - `fun boundIdFor(key: String): String?`
    - `fun addListener(listener: () -> Unit)`

这是整个插件唯一持有可变状态的地方。绑定逻辑是设计中最易出错的部分（见 spec 6.3），因此完全隔离在此、纯逻辑、可测。`clock` 参数注入是为了让测试能控制时间，不依赖真实墙钟。

绑定规则，明确定义以消除歧义：

1. 一条扫描到的真实会话，若其 `id` 尚未出现在上一轮扫描结果中，且 `lastActiveAt >= pending.startedAt`，且 `agentType` 相同，则它是某个 pending 的候选
2. 若同类型有多个 pending 竞争同一个新会话，绑定到 `startedAt` **最晚且不迟于该会话 lastActiveAt** 的那个（最近一次点击「新建」最可能是它）
3. 一个 pending 一旦绑定就不再参与后续绑定
4. 超过 `PENDING_TTL`（30 分钟）仍未绑定的 pending 在 refresh 时被清除

```kotlin
package com.github.izerui.imux.session

import com.github.izerui.imux.model.AgentSession
import com.github.izerui.imux.model.AgentType
import java.time.Duration
import java.time.Instant
import java.util.concurrent.CopyOnWriteArrayList

data class PendingSession(
    val key: String,
    val agentType: AgentType,
    val startedAt: Instant,
)

sealed interface ListEntry {
    data class Existing(val session: AgentSession) : ListEntry
    data class Pending(val pending: PendingSession) : ListEntry
}

/**
 * 列表的全部可变状态集中于此：扫描结果、未绑定的新会话临时条目、绑定关系。
 *
 * 依赖以函数形式注入（scan / clock），使本类完全脱离文件系统与墙钟，便于测试。
 */
class SessionListModel(
    private val scan: () -> List<AgentSession>,
    private val clock: () -> Instant,
) {

    private var sessions: List<AgentSession> = emptyList()
    private val pendings = mutableListOf<PendingSession>()
    private val bindings = mutableMapOf<String, String>()
    private var knownIds: Set<String> = emptySet()
    private val listeners = CopyOnWriteArrayList<() -> Unit>()

    private var pendingSeq = 0

    fun addListener(listener: () -> Unit) {
        listeners.add(listener)
    }

    fun registerPending(agentType: AgentType): PendingSession {
        val pending = PendingSession(
            key = "pending-${pendingSeq++}",
            agentType = agentType,
            startedAt = clock(),
        )
        pendings.add(pending)
        notifyListeners()
        return pending
    }

    fun boundIdFor(key: String): String? = bindings[key]

    fun refresh() {
        val scanned = scan()
        bindNewSessions(scanned)
        expirePendings()
        sessions = scanned
        knownIds = scanned.map { it.id }.toSet()
        notifyListeners()
    }

    fun entries(agentType: AgentType): List<ListEntry> {
        val existing = sessions
            .filter { it.agentType == agentType }
            .map { ListEntry.Existing(it) }
        val stillPending = pendings
            .filter { it.agentType == agentType && it.key !in bindings }
            .map { ListEntry.Pending(it) }
        return stillPending + existing
    }

    /**
     * 把新出现的会话绑定到等待中的 pending。
     * 竞争时选启动时刻最晚、且不迟于该会话活动时刻的 pending —— 最近一次点击最可能是它。
     */
    private fun bindNewSessions(scanned: List<AgentSession>) {
        val fresh = scanned.filter { it.id !in knownIds }
        for (session in fresh.sortedBy { it.lastActiveAt }) {
            val candidate = pendings
                .filter { it.key !in bindings }
                .filter { it.agentType == session.agentType }
                .filter { !it.startedAt.isAfter(session.lastActiveAt) }
                .maxByOrNull { it.startedAt }
                ?: continue
            bindings[candidate.key] = session.id
        }
    }

    private fun expirePendings() {
        val deadline = clock().minus(PENDING_TTL)
        pendings.removeAll { it.key !in bindings && it.startedAt.isBefore(deadline) }
    }

    private fun notifyListeners() {
        listeners.forEach { it() }
    }

    private companion object {
        val PENDING_TTL: Duration = Duration.ofMinutes(30)
    }
}
```

注意 `entries` 把 pending 放在前面：新建的会话应当出现在分组顶部，与「最近活动优先」的排序意图一致。

因此**不能复用** JetBrains 的 `TerminalViewFileEditor`：其 `dispose()` 的字节码是

```kotlin
    override fun getFile(): VirtualFile = virtualFile

    override fun setState(state: FileEditorState) = Unit

    override fun getState(level: FileEditorStateLevel): FileEditorState = FileEditorState.INSTANCE

    override fun isModified(): Boolean = false
```

```kotlin
package com.github.izerui.imux.terminal

import com.github.izerui.imux.model.AgentType
import com.intellij.openapi.Disposable
import com.intellij.openapi.components.Service
import com.intellij.openapi.fileEditor.FileEditorManager
import com.intellij.openapi.project.Project
import com.intellij.terminal.frontend.view.TerminalView
import kotlinx.coroutines.cancel
import org.jetbrains.plugins.terminal.TerminalToolWindowTabsManager

/**
 * 拥有所有活着的终端 view，按 key 索引。
 *
 * 所有权规则：view 归本服务所有。关闭 editor tab 不取消它的 CoroutineScope，
 * 因此关标签页不会中断会话；再次打开时把同一个 view 挂回新的 tab。
 */
@Service(Service.Level.PROJECT)
class TerminalHost(private val project: Project) : Disposable {

    private val views = mutableMapOf<String, TerminalView>()

    /**
     * 每个 key 对应的虚拟文件实例必须缓存并复用。
     * FileEditorManager 以 VirtualFile 实例为标签页身份：传同一个实例是「切到该标签页」，
     * 每次新建实例则会不断开出重复标签页。
     */
    private val files = mutableMapOf<String, AgentTerminalVirtualFile>()

    /** 启动一个全新会话（不带 resume），返回内部 key。 */
    fun openNew(agentType: AgentType, tabTitle: String): String {
        val key = "new-${agentType.name}-${System.nanoTime()}"
        open(key, agentType, newCommand(agentType), tabTitle)
        return key
    }

    /** 打开一个已有会话；若其终端已在运行则切到该标签页而不重启。 */
    fun openResume(agentType: AgentType, sessionId: String, tabTitle: String) {
        open(sessionId, agentType, resumeCommand(agentType, sessionId), tabTitle)
    }

    fun isRunning(key: String): Boolean = views.containsKey(key)

    private fun open(key: String, agentType: AgentType, command: List<String>, tabTitle: String) {
        val file = files.getOrPut(key) {
            val view = views.getOrPut(key) { createView(command) }
            AgentTerminalVirtualFile(tabTitle, view, key)
        }
        FileEditorManager.getInstance(project).openFile(file, true)
    }

    private fun createView(command: List<String>): TerminalView =
        TerminalToolWindowTabsManager.getInstance(project)
            .createTabBuilder()
            .workingDirectory(projectPath())
            .shellCommand(command)
            .shouldAddToToolWindow(false)     // 由本服务安置，不进工具窗口
            .closeOnProcessTermination(false) // 进程结束后保留 UI 供回看
            .createTab()
            .view

    private fun projectPath(): String =
        project.basePath ?: System.getProperty("user.home")

    private fun newCommand(agentType: AgentType): List<String> = when (agentType) {
        AgentType.CLAUDE -> listOf("claude")
        AgentType.CODEX -> listOf("codex")
    }

    private fun resumeCommand(agentType: AgentType, sessionId: String): List<String> =
        when (agentType) {
            AgentType.CLAUDE -> listOf("claude", "--resume", sessionId)
            AgentType.CODEX -> listOf("codex", "resume", sessionId)
        }

    /**
     * 项目关闭时终结所有会话。这是唯一该杀进程的地方。
     *
     * 若 Step 1 验证出 tabs manager 会兜底释放 scope，此处的显式 cancel 应改为无操作，
     * 以免重复取消。以实测结论为准，并把结论写进本注释。
     */
    override fun dispose() {
        views.values.forEach { it.coroutineScope.cancel() }
        views.clear()
        files.clear()
    }

    companion object {
        fun getInstance(project: Project): TerminalHost = project.getService(TerminalHost::class.java)
    }
}
```

```kotlin
        val title: String,
        /** 该会话的终端此刻是否在本 IDE 中活着。仅反映本 IDE 启动的终端，见下方说明。 */
        val running: Boolean,
    ) : NodeData
    data class PendingSession(val agentType: AgentType, val key: String) : NodeData
    data class ShowMore(val agentType: AgentType) : NodeData
}

class AgentSessionTree(
    private val project: Project,
    private val model: SessionListModel,
) {

    private val root = DefaultMutableTreeNode("root")
    private val treeModel = DefaultTreeModel(root)
    private val tree = Tree(treeModel).apply {
        isRootVisible = false
        showsRootHandles = true
        selectionModel.selectionMode = TreeSelectionModel.SINGLE_TREE_SELECTION
    }

    /** 每个分组当前展示的条数上限，点「显示更多」后递增。 */
    private val limits = mutableMapOf(AgentType.CLAUDE to PAGE_SIZE, AgentType.CODEX to PAGE_SIZE)

    init {
        tree.addMouseListener(object : MouseAdapter() {
            override fun mouseClicked(event: MouseEvent) {
                if (event.clickCount != 2) return
                handleActivate(tree.getPathForLocation(event.x, event.y) ?: return)
            }
        })
        model.addListener { reload() }
    }

    fun component(): JComponent = tree

    fun reload() {
        val expanded = expandedGroups()
        root.removeAllChildren()
        AgentType.entries.forEach { addGroup(it) }
        treeModel.reload()
        restoreExpansion(expanded)
    }

    private fun addGroup(agentType: AgentType) {
        val groupNode = DefaultMutableTreeNode(NodeData.Group(agentType))
        root.add(groupNode)

        val entries = model.entries(agentType)
        val limit = limits.getValue(agentType)

        entries.take(limit).forEach { entry ->
            val data = when (entry) {
                is ListEntry.Existing -> NodeData.Session(
                    agentType,
                    entry.session.id,
                    entry.session.title,
                    running = TerminalHost.getInstance(project).isRunning(entry.session.id),
                )
                is ListEntry.Pending -> NodeData.PendingSession(agentType, entry.pending.key)
            }
            groupNode.add(DefaultMutableTreeNode(data))
        }

        if (entries.size > limit) {
            groupNode.add(DefaultMutableTreeNode(NodeData.ShowMore(agentType)))
        }
    }

    private fun handleActivate(path: TreePath) {
        val node = path.lastPathComponent as? DefaultMutableTreeNode ?: return
        when (val data = node.userObject) {
            is NodeData.Session -> {
                TerminalHost.getInstance(project).openResume(data.agentType, data.id, data.title)
                // 打开终端不会触发扫描，需显式重绘以让「运行中」标识立即生效
                reload()
            }

            is NodeData.PendingSession -> {
                val boundId = model.boundIdFor(data.key)
                if (boundId != null) {
                    TerminalHost.getInstance(project)
                        .openResume(data.agentType, boundId, "会话 ${boundId.take(8)}")
                    reload()
                }
                // 未绑定时无操作：终端已在新建时打开，双击无额外语义
            }

            is NodeData.ShowMore -> {
                limits[data.agentType] = limits.getValue(data.agentType) + PAGE_SIZE
                reload()
            }

            else -> Unit
        }
    }

    private fun expandedGroups(): Set<AgentType> = root.children().toList()
        .filterIsInstance<DefaultMutableTreeNode>()
        .filter { tree.isExpanded(TreePath(it.path)) }
        .mapNotNull { (it.userObject as? NodeData.Group)?.agentType }
        .toSet()

    private fun restoreExpansion(expanded: Set<AgentType>) {
        root.children().toList()
            .filterIsInstance<DefaultMutableTreeNode>()
            .filter { (it.userObject as? NodeData.Group)?.agentType in expanded }
            .forEach { tree.expandPath(TreePath(it.path)) }
    }
}
```

节点显示文本依赖 `NodeData` 的 `toString`。为得到可读标签，在 `NodeData` 各实现上补 `override fun toString()`：`Group` 返回 `"Claude Code"` / `"Codex"`，`Session` 返回 `title`，`PendingSession` 返回 `"新会话（等待首条消息）"`，`ShowMore` 返回 `"显示更多…"`。

```kotlin
package com.github.izerui.imux.watch

import com.intellij.openapi.Disposable
import com.intellij.openapi.application.ApplicationManager
import com.intellij.openapi.diagnostic.logger
import java.nio.file.FileSystems
import java.nio.file.Files
import java.nio.file.Path
import java.nio.file.StandardWatchEventKinds
import java.nio.file.WatchService
import java.util.concurrent.atomic.AtomicBoolean

/**
 * 监听 CLI 会话库目录的变化。
 *
 * 这两个目录位于项目之外，IDEA 自身的 VFS 不覆盖，只能用 NIO WatchService。
 * 变化事件可能密集到来（CLI 持续追加写），因此做了合并去抖。
 */
class SessionStoreWatcher(
    private val paths: List<Path>,
    private val onChange: () -> Unit,
) : Disposable {

    private val running = AtomicBoolean(false)
    private var watchService: WatchService? = null

    fun start() {
        if (!running.compareAndSet(false, true)) return

        val service = FileSystems.getDefault().newWatchService()
        watchService = service

        paths.filter { Files.isDirectory(it) }.forEach { path ->
            runCatching {
                path.register(
                    service,
                    StandardWatchEventKinds.ENTRY_CREATE,
                    StandardWatchEventKinds.ENTRY_MODIFY,
                    StandardWatchEventKinds.ENTRY_DELETE,
                )
            }.onFailure { LOG.warn("无法监听目录 $path", it) }
        }

        Thread({ loop(service) }, "ai-agent-session-watcher").apply {
            isDaemon = true
            start()
        }
    }

    private fun loop(service: WatchService) {
        while (running.get()) {
            val key = runCatching { service.take() }.getOrNull() ?: return
            key.pollEvents()
            // 合并短时间内的连续事件：CLI 写入是持续追加的，逐个事件刷新会过于频繁
            Thread.sleep(DEBOUNCE_MS)
            service.poll()?.reset()
            key.reset()

            if (running.get()) {
                ApplicationManager.getApplication().invokeLater { onChange() }
            }
        }
    }

    override fun dispose() {
        running.set(false)
        runCatching { watchService?.close() }
    }

    private companion object {
        val LOG = logger<SessionStoreWatcher>()
        const val DEBOUNCE_MS = 800L
    }
}
```

注意 `onChange` 通过 `invokeLater` 派发到 EDT——`SessionListModel.refresh()` 会触发 UI 重建，必须在 EDT 上执行。
