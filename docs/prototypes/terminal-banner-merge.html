终端顶部横幅：两条合成一条

现在终端顶部有两条横幅：一条是结对编程和先聊再做的入口，一条是手机连接状态，叠在一起占了两行，而且内容有重复（两条都是“这个会话的协作方式”）。 下面给出三种合并方案。用上方开关切换状态和编辑器宽度，可以对比每种方案在“审查进行中 + 已连接手机”“手机重连中”“窄窗口”这些情况下的表现。 方向 A、B 只用平台现有组件（ActionLink、JBLabel、弹出菜单）就能实现；方向 C 的胶囊需要少量自绘。

方向 A · 左右分区推荐

左边是这个会话的 AI 协作（结对编程、先聊再做），右边是手机连接，中间用细分隔线隔开。手机部分只显示渠道和机器人名，点开下拉菜单才看到说明、换绑和断开。

⏺ 好的，先看一下两个横幅的实现…
好处：左边保持现有横幅的位置和顺序，老用户不用重新找；手机状态固定在右端，扫一眼就知道连没连上；重连中时右侧圆点和文字都变黄。
代价：换绑、断开要多点一下；窄窗口下左侧链接会被挤成省略号，需要定义收缩顺序（先收“不再提示”，再收机器人名，只留手机图标）。

方向 B · 一句状态 + 两个菜单

左边只放一句当前最重要的状态，优先级是：审查进行中 > 手机重连中 > 已连接手机 > 结对伙伴已就绪 > 空闲提示。右边把所有操作收进「结对编程 ▾」「手机 ▾」两个菜单按钮，「先聊再做」仍然是一个直接点击的按钮。

好处：最整洁，宽度变化时最稳定；以后再加新的协作功能，只需要往菜单里加一项，不用改横幅布局。
代价：「开启结对编程」「审查一次」从一键直达变成两步，常用操作变慢；同一时间只显示一种状态，审查进行中时手机状态只剩右侧一个小圆点。

方向 C · 原横幅不动，手机变成右端胶囊

结对编程这部分完全保持原样。手机连接显示成右端一枚小胶囊，绿色表示在线、黄色表示重连中；鼠标悬停时胶囊向左展开，露出「换绑」「断开」。说明文字放进悬停提示。

好处：改动最小，现有横幅的代码和行为几乎不用动；胶囊在色彩上最醒目，一眼能看出“这个终端连着手机”。
代价：悬停展开在 Swing 里要自己处理鼠标事件，键盘无法操作（需要再补一个右键菜单）；胶囊需要自绘圆角背景，是三个方案里唯一需要自定义绘制的。

三个方案都满足：只有一条横幅；「不再提示」只收起结对编程的入口，「先聊再做」和手机状态始终保留；手机未连接时手机部分完全不出现；文字全部跟随 imux 语言设置刷新。
