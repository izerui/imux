终端顶部横幅：从「四个入口排一行」改成「状态先说话」

现在这条横幅一直是蓝色信息底，左边一句话、右边结对编程 / 先聊再做 / 会话轨迹 / 手机四段文字链接。下面三版都用真实图标和现有文案，切换上面的场景、宽度、主题看各自表现。点横幅上的按钮可以打开对应的弹出层。

颜色失去意义信息蓝一直开着，真正出事（手机断线、审查失败）时没有更强的信号可用。
空闲时最吵没事做时左边最显眼的位置被一句固定的引导语长期占用。
状态散在四处结对在左边的句子里，轨迹写在链接文字里，手机靠圆点，讨论也靠圆点。
修复要两步断线、过期、失败都要先点开下拉再找操作，横幅本身不给直接按钮。

方向 A · 工具条

参照：IntelliJ 编辑器顶部的 Diff / Git 工具栏

横幅退回中性底，四个功能变成带角标的工具按钮。左边只在出事时说话，说话时整条染色，并把唯一要做的那个动作直接放在句子后面。

交互规则

  • 底色只有四种含义：中性 = 没事，蓝 = 正在进行，黄 = 需要你处理，绿 = 刚完成（8 秒后回中性）。
  • 按钮的角标说长期状态：绿点 = 开着，黄点 = 有问题，转圈 = 正在跑；面板或窗口打开时按钮呈按下态。
  • 变窄时先去掉按钮文字，只留图标，左边的句子最后才截断。

平台实现

ActionToolbar + ToggleAction，角标用 BadgeIconSupplier，染色复用 JBUI.CurrentTheme.Banner 的三种底色。

方向 B · 一句话 + 协作中心

参照：macOS 控制中心、JetBrains 状态栏的 Git 小部件

左边永远只说当前最要紧的一件事，同时还有别的事就给出「另有 N 件」。右边四个功能收成一个按钮，点开是一张协作中心卡片，每个功能一行：现在是什么状态、下一步能做什么，都在这一行里。

交互规则

  • 优先级：手机断线 / 失败 > 审查进行中 > 刚审查完 > 讨论开着 > 结对就绪 > 空闲。
  • 入口按钮里四个小图标的角标和卡片里各行一致，不点开也能看出哪个功能开着。
  • 卡片里每行最多两个按钮；更细的选项（换绑哪个机器人、换哪个结对伙伴）收在按钮的二级菜单里。

平台实现

卡片用 JBPopupFactory.createComponentPopupBuilder + UI DSL 的 panel { row {} }，入口是一个 ActionButton。

方向 C · 平时不占行，有事才出条

参照：编辑器浮动工具栏 + EditorNotificationPanel

去掉常驻横幅，终端从第一行开始。四个功能缩成终端右上角的浮动图标组，平时半透明。只有正在审查、审查结果、连接出错这类需要你看一眼的事件，才在顶部滑出一条通知；处理完或 8 秒后收起。

交互规则

  • 浮动图标组平时 55% 不透明，鼠标靠近或有角标时变成不透明。
  • 同时有多个事件时只出一条，按 B 的优先级排；其余在图标角标上体现。
  • 第一次打开终端时用一个 GotIt 气泡指一下图标组，解决入口不好找的问题。

平台实现

图标组参照编辑器浮动工具栏（FloatingToolbar）的做法挂在 JBLayeredPane 上，和现有「滚到底部」按钮放在同一层；事件条用 EditorNotificationPanel 的三种 Status；引导用 GotItTooltip。

我的推荐是 A。它解决了上面四个问题里的全部，入口照样看得见，改动也最小。如果你更想把终端的竖向空间省下来，就选 C；B 的卡片适合以后功能还会继续加的情况。也可以拼起来，例如用 A 的横幅，再加上 B 的卡片作为窄屏时的「更多」。
