# 六个候选

共同输入见 spec.md。三个选中方向形成独立 HTML；其余三个以缩略图保留。

## A 快速弹窗（完整）
设计思路：借 Steve Krug 的最小认知负担原则，不模仿具名作品。
骨架：终端右上入口下方展开浮层；身份、分类、列表、来源逐层展开。
素材：真实智能体和平台图标，项目已有终端结构。
取舍：最小界面占用；长清单需要滚动。
Form 来自内容：这是一项临时确认，保留工作现场。

## B 常驻侧栏（完整）
设计思路：借 Alan Cooper 的对象与任务组织方法。
骨架：终端与能力侧栏并列，选中会话和侧栏身份一致。
素材：真实终端层级和工具来源。
取舍：适合反复检查，但占终端宽度。
Form 来自内容：信息属于当前会话，与工作并排。

## C 分类详情窗口（完整）
现实参照：项目已有添加机器人对话框的左右分栏，以及 JetBrains 设置窗口的分类方式。
证据：docs/prototypes/add-robot-dialog/direction-approved.md；该处用户已选择左列表右内容。
骨架：居中详情窗口，左分类、右列表；浅色初始主题。
取舍：信息容量大，但查看时暂时离开终端操作。
Form 来自内容：能力类型有清楚的分类边界。

## D 底部检查区（备选）
现实参照：JetBrains 工具窗口的底部停靠形式。
骨架：终端上方保留，底部按资源、状态、来源排列。
取舍：不压缩终端宽度，但占垂直空间。

## E 会话树内展开（备选）
风格探索：兼容 IDE 语境的实用主义分类结构，参考风格库 web 15。
骨架：会话树节点下展开 MCP、技能、规则。
取舍：发现性强，名称长时容易拥挤；不采用该风格的渐变和大色块。

## F 会话资料标签页（备选）
风格探索：功能主义信息列表，参考风格库 web 17；去除网页社区的视觉修辞。
骨架：在终端旁打开一个资料标签页，以表格展示来源。
取舍：空间充分，但容易与实际会话失去关联。

风格总览已查看。项目已有原生风格优先，不为制造差异更换产品视觉语言。
